# Pilot Test Scripts
## Overview

This directory contains the processing scripts developed for the pilot investigation of the **Aging Adult Brain Connectome (AABC) dataset**, conducted as part of a research exchange at the University of Bordeaux.

The workflow was adapted from the original **Project TARRAGON processing pipeline**, initially developed for the Midnight Scan Club (MSC) dataset. Its purpose is to generate quantitative maps of local functional brain organisation using the unnormalised Vogt–Bailey (VB) Index, calculated from resting-state functional MRI (fMRI) data.

Although modifications were necessary to accommodate differences in dataset organisation, acquisition structure and preprocessing requirements, the core computational methodology remains consistent with the original MSC implementation. Specifically, both workflows incorporate:

1. Validation of fMRIPrep derivatives and associated confound parameters.
2. Nuisance regression using a 36-parameter (36P) model combined with 128-second high-pass filtering.
3. Calculation of the unnormalised volumetric VB Index using seven-voxel (VB7) and 27-voxel (VB27) neighbourhoods.

No additional spatial smoothing is applied during the denoising stage.

The adaptations primarily concern participant and session identification, input/output directories, acquisition-specific file handling, processing manifests and execution management.

### Scope of the Provided Scripts

The scripts included in this directory correspond to the initial AABC pilot analysis of **participant HCA8889115, Visit 1 (V1)**.

These particular scripts were selected for inclusion because V1 was independently preprocessed from the original AABC imaging data using **fMRIPrep v22.1.1**, providing a complete and documented workflow from raw MRI acquisitions through to the final VB maps.

Subsequent analyses of Visits 2–4 (V2–V4) used fMRIPrep derivatives separately generated by a collaborator using **fMRIPrep v25.2.5**. The same downstream TARRAGON methodology was then applied, comprising 36P nuisance regression, high-pass filtering and native-space VB calculation.

Consequently, the V1 scripts are provided as a reference implementation of the complete workflow. They can be adapted for additional participants or visits by updating the relevant directories, participant identifiers, acquisition labels, manifest handling and other dataset-specific settings. The underlying denoising and VB calculation methods can remain unchanged, provided the required input data and metadata are compatible.

The scripts should not be considered universally executable without these adjustments.

## 1. Processing Workflow

The complete AABC V1 processing workflow consists of six stages.

| Script | Description |
|---|---|
| `01_prepare_bids.py` | Identifies the original AABC imaging data and prepares a BIDS-compatible dataset for preprocessing. |
| `02_run_fmriprep.sh` | Executes fMRIPrep v22.1.1 for structural and functional MRI preprocessing. |
| `03_preflight_derivatives.py` | Validates the resulting fMRIPrep derivatives and generates a manifest of acquisitions suitable for further processing. |
| `04_denoise_36P.py` | Performs 36-parameter nuisance regression and 128-second DCT high-pass filtering. |
| `05_run_vb_fmriprep.py` | Calculates unnormalised volumetric VB7 and VB27 maps from the denoised functional images. |
| `06_register_native_vb_to_MNI.sh` | Transforms completed native-space VB maps into MNI space using existing spatial transformations. |

The accompanying `config.yaml` documents the original V1 configuration and processing paths.

The pipeline follows the sequence:

**Raw AABC MRI data → BIDS organisation → fMRIPrep → Preflight validation → 36P denoising → Native-space VB calculation → Optional spatial registration**

Importantly, spatial normalisation is not required before VB calculation. The preferred approach is to compute VB directly from the denoised data in native functional space and subsequently transform the completed maps into a common reference space when spatial comparisons are required.

## 2. Dataset and Acquisition Structure

The pilot investigation uses resting-state fMRI acquisitions from participant **HCA8889115**, drawn from the AABC dataset.

Each visit contains four independent resting-state acquisitions:

| Acquisition | Phase-encoding direction | Run |
|---|---|---|
| REST1_AP | Anterior–posterior (AP) | 1 |
| REST1_PA | Posterior–anterior (PA) | 1 |
| REST2_AP | Anterior–posterior (AP) | 2 |
| REST2_PA | Posterior–anterior (PA) | 2 |

Each acquisition is processed independently to preserve run-specific functional information and allow subsequent assessment of run-to-run reproducibility.

The original BIDS conversion distinguishes these acquisitions using the corresponding `dir-` and `run-` entities. For example:

`sub-HCA8889115_ses-V1_task-rest_dir-AP_run-1_bold.nii.gz`

The acquisition inventory also identifies the relevant reversed phase-encoding fieldmaps, grouped as `SpinEchoFieldMap1` for REST1 and `SpinEchoFieldMap3` for REST2.

These associations are established using the source acquisition metadata rather than assumed from filenames alone.

## 4. fMRI Preprocessing

### 4.1 BIDS Preparation

The original AABC functional and structural imaging data were organised into a BIDS-compatible structure using `01_prepare_bids.py`.

The script first performs an inventory of the available acquisitions and associated metadata. Following validation, the `--build` option constructs the BIDS directory, creating hardlinks to the original NIfTI images and copying the required JSON metadata.

The conversion preserves the available acquisition parameters without introducing estimated or assumed timing and geometric information.

Consistency checks are included for the phase-encoding direction and relevant BIDS metadata.

Since hardlinks reference the same underlying file data, neither the original NIfTI images nor the linked copies should be modified in place.

### 4.2 fMRIPrep

The V1 data were independently preprocessed using **fMRIPrep v22.1.1**, executed through the software module available on Pavie.

The workflow performs standard structural and functional MRI preprocessing, including motion estimation and correction, susceptibility-distortion correction where supported by the available fieldmaps, functional-to-anatomical registration and spatial normalisation.

The original execution configuration specified:

| Parameter | Configuration |
|---|---|
| fMRIPrep version | 22.1.1 |
| Execution environment | Pavie software module |
| Maximum processes | 20 |
| OMP threads | 8 |
| Memory limit | 100,000 MB |
| Functional/native output | `func` |
| Anatomical output | `T1w` |
| Standard-space output | `MNI152NLin2009cAsym`, 2 mm |

The specified computational resources represent processing limits rather than exclusive resource reservations.

The fMRIPrep derivatives were subsequently used as input to the original TARRAGON denoising and VB calculation procedures.

### 4.3 Preflight Validation

Following fMRIPrep, `03_preflight_derivatives.py` verifies the availability and consistency of the preprocessed functional images, corresponding brain masks, confound regressors and relevant acquisition metadata.

The script also prepares a processing manifest identifying acquisitions suitable for downstream analysis.

For the original V1 configuration, the expected manifest comprises eight entries, corresponding to four resting-state runs represented in two spatial configurations.

Downstream processing should only proceed once all expected entries are marked `READY`.

## 5. Nuisance Regression and Temporal Filtering

The functional images undergo additional denoising using `04_denoise_36P.py`, following the methodology established in the original MSC pipeline.

A **36-parameter nuisance regression model** is constructed from nine primary nuisance signals:

- Six rigid-body motion parameters (three translations and three rotations).
- Mean white matter signal.
- Mean cerebrospinal fluid signal.
- Global signal.

For each primary regressor, four terms are included: the original signal, its temporal derivative, its squared value and the squared temporal derivative.

This produces a total of 36 nuisance regressors.

Temporal high-pass filtering is implemented using a discrete cosine transform (DCT) basis with a **128-second cutoff period**. Nuisance regression and high-pass filtering are performed jointly within the same regression model to reduce the possibility of reintroducing previously removed signal components.

Initial non-steady-state volumes are removed where identified. No additional spatial smoothing or framewise motion censoring is performed.

The regression is implemented through an orthogonal projection derived from singular value decomposition (SVD). Quality-control procedures verify the numerical validity of the residual time series and confirm that the fitted nuisance components have been sufficiently removed.

The denoised functional images are retained in their respective input spatial grids, without additional spatial resampling during this stage.

## 6. Vogt–Bailey Index Calculation

Following denoising, the unnormalised volumetric Vogt–Bailey Index is calculated using `05_run_vb_fmriprep.py`.

The script invokes the original `vb_tool` executable and supports two neighbourhood configurations.

**VB7** uses a seven-voxel neighbourhood comprising the central voxel and its six directly adjacent neighbours.

**VB27** uses a 27-voxel neighbourhood corresponding to a 3 × 3 × 3 cube centred on each voxel.

Both configurations use the unnormalised graph Laplacian implementation of the VB toolbox.

VB calculation is performed independently for each resting-state acquisition. The resulting maps are saved without modification to the original toolbox-generated NIfTI values.

For the subsequent longitudinal investigation, native functional space was prioritised for VB calculation to minimise the potential influence of prior spatial normalisation and interpolation on local voxelwise functional relationships.

### Spatial Registration of VB Maps

When maps from different acquisitions or visits must be compared, the completed native-space VB maps can be transformed into a common anatomical or standard space using the spatial transformations produced during preprocessing.

This distinction is important: the preferred workflow transforms the **completed VB maps**, rather than transforming the functional time series into standard space before calculating VB.

The provided `06_register_native_vb_to_MNI.sh` script was developed for the original V1 investigation and must be reviewed and adapted before being applied to other visits or spatial references.

## 7. Execution Instructions

The following commands reproduce the intended execution sequence for the original V1 configuration on Pavie.

### Step 1 — Initialise the Python environment

```bash
module purge
module load python/3.12.9
unset PYTHONHOME PYTHONPATH
```

### Step 2 — Inspect and prepare the BIDS dataset

```bash
python 01_prepare_bids.py
```

After reviewing the acquisition inventory:

```bash
python 01_prepare_bids.py --build
```

Validate the generated BIDS dataset using a BIDS validator, where available. Any validation errors should be investigated before continuing.

### Step 3 — Run fMRIPrep

Ensure that a valid FreeSurfer licence is available and that sufficient disk space and computational resources have been allocated.

```bash
export FS_LICENSE=/path/to/your/valid/FreeSurfer/license.txt

bash 02_run_fmriprep.sh
```

The execution script performs resource checks and requests confirmation before initiating preprocessing.

### Step 4 — Validate the fMRIPrep derivatives

Following successful preprocessing, open a Python 3.12 environment and run:

```bash
python 03_preflight_derivatives.py
```

Confirm that all eight expected V1 manifest entries have `READY` status.

### Step 5 — Perform 36P denoising

```bash
python 04_denoise_36P.py --all --space both
```

The script writes the denoised functional images, processing metadata and quality-control reports to `fMRIPrep_VB/`.

### Step 6 — Calculate the VB maps

An individual acquisition may first be tested using:

```bash
python 05_run_vb_fmriprep.py \
    --run REST1_PA \
    --space MNI152NLin2009cAsym \
    --neighbourhood 7 \
    --dry-run
```

Following inspection, execute the selected condition:

```bash
python 05_run_vb_fmriprep.py \
    --run REST1_PA \
    --space MNI152NLin2009cAsym \
    --neighbourhood 7
```

To process all four acquisitions and both neighbourhood configurations across the two requested spaces:

```bash
python 05_run_vb_fmriprep.py \
    --all-runs \
    --space both \
    --neighbourhood both \
    --heartbeat-seconds 10
```

These commands reflect the original V1 pipeline. Before re-execution, verify that the relevant paths, software environments, manifests and processing options match the intended dataset.

## 8. Adaptation to Other Participants and Visits

The provided scripts are configured for participant HCA8889115, V1. They are intended to serve as a documented starting point for further AABC analyses rather than a fully generalised processing package.

For another participant or visit, the following may require modification:

| Component | Required adaptation |
|---|---|
| Participant and visit identifiers | Update subject and session references throughout the scripts and configuration files. |
| Source data directories | Specify the appropriate AABC functional and structural imaging inputs. |
| fMRIPrep configuration | Confirm the preprocessing version, output spaces, fieldmap availability and processing options. |
| Preflight manifest | Update expected acquisitions and ensure that the file-discovery logic matches the available derivatives. |
| Denoising outputs | Update the experiment directory and select the relevant participant, visit and spatial representation. |
| VB outputs | Update hardcoded paths, acquisition labels and expected output locations. |
| Spatial registration | Select the correct visit-specific transformations, anatomical references and common comparison space. |

For V2–V4, the preprocessing stage was performed separately using fMRIPrep v25.2.5, and the downstream processing scripts were adapted to read those existing derivatives directly. It was therefore unnecessary to repeat the original V1 BIDS conversion and fMRIPrep execution stages.

The denoising and VB calculation methodology remained consistent with the original pipeline.

However, compatibility of the derivatives must be verified for each new processing batch. In particular, differences in BIDS naming conventions, directory structure, preprocessing versions and spatial references may require changes beyond simple path replacement.
